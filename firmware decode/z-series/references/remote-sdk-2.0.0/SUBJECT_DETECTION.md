# 主体检测的 SDK 与协议对照

本页用一个与 AI 固件研究直接相关的例子，连接协议属性、SDK 枚举和按机型划分的配置。这里记录的是 SDK 文档与配置声明，没有连接相机验证。

## 两个编号层

| 功能 | MAID capability ID | MTP 属性码 | 原始定义 |
| --- | --- | --- | --- |
| 照片主体检测 | `AFSubjectDetection`：34118／`0x8546` | `0x0001D005` | Z f 第 302 页；Z8 第 285 页 |
| 视频主体检测 | `MovieAFSubjectDetection`：34119／`0x8547` | `0x0001D006` | Z f 第 375 页；Z8 第 357 页 |

机型 PDF 见[协议目录](PROTOCOLS.md)，SDK 名称和枚举见 [Maid3d1.h](original/Module/Win/HeaderFile/Maid3d1.h)，配置值见 [range_values.csv](indexes/range_values.csv)。

Z f 和 Z8 的照片属性表均使用 `UINT8`、Enumeration、Get／Set，默认值为 1。两份表中的数值含义一致：

| 数值 | 含义 |
| ---: | --- |
| 0 | 关闭 |
| 1 | 自动 |
| 2 | 人物 |
| 3 | 动物 |
| 4 | 车辆 |
| 5 | 鸟类 |
| 6 | 飞机 |

共同头文件的枚举还包含 `Train`（按顺序为 7），但上述两份照片属性表没有列出 7。不能把共同头文件的最大枚举值当作每台相机都支持的选项。

## 配置标签下的实际差异

下表逐项来自 `RangeValue.config`，保留原始顺序。所列块中照片与视频主体检测的枚举一致，默认值均为 1。

| model 标签 | version 标签 | 枚举原文 | 包含数值 5 |
| --- | --- | --- | --- |
| `Z f` | `1.0` | `1,2,3,4,6,0` | 否 |
| `Z f` | `2.0`、`3.0` | `1,2,3,5,4,6,0` | 是 |
| `Z 8` | `common` | `1,2,3,4,6,0` | 否 |
| `Z 8` | `2.0`、`3.0`、`4.0`、`5.0` | `1,2,3,5,4,6,0` | 是 |
| `Z 9` | `2.0`、`3.0` | `1,2,3,4,0` | 否 |
| `Z 9` | `4.0`、`5.0` | `1,2,3,5,4,6,0` | 是 |
| `Z6_3` | `1.0` | `1,2,3,4,6,0` | 否 |
| `Z6_3` | `2.0` | `1,2,3,4,5,6,0` | 是 |
| `Z5_2` | `common` | `1,2,3,5,4,6,0` | 是 |
| `ZR` | `1.0`、`2.0` | `1,2,3,5,4,6,0` | 是 |

这是明确的配置差异，支持继续研究 SDK 如何选择版本块及开放鸟类检测选项。它不证明同名配置标签恰好对应哪个相机固件版本，也不证明“没有独立鸟类选项”就完全不能识别鸟类。`Z50_2` 等块没有在此表展开，不代表缺少识别能力；继承和运行时能力查询尚未还原。

## 对固件研究的用途

协议属性码可用于在已解包固件中寻找属性分发表、设置值校验和处理函数。确认入口后，可追踪这些值是否选择不同模型、改变阈值、切换跟踪策略或仅影响 UI；具体机制尚未确定。

这个入口也能帮助解释[现有 AI／DSP 比较](../../analysis/ai_comparison/REPORT.md)中“公共推理程序和部分网络候选数据相同，而功能仍可能不同”的现象。模型身份、SDK 可用选项和最终对焦表现应分别验证。

最小验证链为：**机型 PDF 定义 → SDK 配置作用域 → 实际相机属性描述 → 固件处理函数 → 算法调用**。本次整理完成前两项的资料准备，未宣称后面三项已验证。

## 后续固件分析

[Z8 × SDK 分析](../../analysis/z8_sdk_subject/REPORT.md)已进一步定位八版固件的照片／视频设置函数：1.01 拒绝鸟类值 `5`，2.00 起两者均将该值传给机内设置服务；内部编号分别为 `0x0600069A`、`0x06001254`。已完成 4,096 例隔离指令验证。实际相机属性描述、设置是否成功应用，以及主体模式到 DSP 参数的完整连接仍未验证。
