# Z8 C 3.11 机内版本页显示标记

已定位普通「固件版本」页面的 C 版本专用 getter。仅替换它的尾调用，可以把机内页面的 C 版本显示为 `3.11 P`，保留真实固件版本数据及原版本查询函数的返回码。此结论来自静态分析和局部 Unicorn 执行；尚未验证相机实际画面。

## 固定输入与范围

- 输入：`analysis/Z_8_0311/eg2070_0311b0.bi`
- SHA-256：`f85e0138e2f5e660ece8560de62e0d12cb795e0e14983e50f20b61dce906c46c`
- EG 映射基址：`0x40160000`，下列代码地址均为运行地址。
- 修改目标是普通固件版本页中的 C 行，不是固件包元数据、PTP 版本、升级比较逻辑或调试版本页。
- 探针不会修改输入文件，也不会生成可安装固件。

## 调用链和修改点

| 地址 | 已确认作用 |
|---|---|
| `0x405A259C` | 固件版本页面 builder；调用 `0x403EC384(0x111)` 选择普通或调试分支 |
| `0x42B252A0` | 普通页面的 7 组可见性检查/getter 函数表；第一组是 C 行 |
| `0x405AB414` | C 行可见性检查，返回 1 |
| `0x405AB41C` | C getter：`x0` 为容量 10 的版本缓冲区，`x1` 为容量 3 的标签缓冲区 |
| `0x42B2F6F4` | `C\0` 标签 |
| `0x405AB454` | getter 的尾调用 `b 0x403EDDAC`；原字节 `56 0a f9 17` |
| `0x403EDDAC` | 版本查询包装函数；C getter 传入 `w0=13, x1=版本缓冲区, w2=10` |
| `0x405A7A88` | 版本显示 helper；把首字符 `0` 替换为空格，再提交 ASCII 文本 |
| `0x403F2920` | ASCII 文本转换/提交函数；其复制上限为 50 字节，未发现 5 字符截断 |

普通 builder 在 `0x405A2808` 间接调用 getter，版本缓冲区为 `sp+0x20`，标签缓冲区为 `sp+0x2c`；在 `0x405A2868` 调用版本显示 helper。共享的显示 helper 还用于其他版本和升级页面，因此应修改 C getter 的专用尾调用。

建议在已有诊断 payload 中增加下列 36 字节函数，并将 `0x405AB454` 的 `b` 重定向到该函数。原 getter 已在尾调用前恢复 `x19` 和 `LR`，因此 trampoline 需要自行保存这两个寄存器：

```asm
ui_version:
    stp x19, x30, [sp, #-16]!
    mov x19, x1
    bl  stock_version              // 0x403EDDAC
    movz x8, #0x2e33
    movk x8, #0x3131, lsl #16
    movk x8, #0x5020, lsl #32
    str x8, [x19]                  // "3.11 P\0\0"
    ldp x19, x30, [sp], #16
    ret
```

这段代码只覆盖传入的临时显示缓冲区。它保留 `w0`，且没有改动全局版本字符串 `Ver.03.11.b0`。标记是这个固定构建的静态字符串：即使 backend 返回错误，缓冲区也会写入标记；错误返回码仍原样保留。不要把该行为解释成查询成功。

## 可复现的局部执行

```sh
/tmp/nikon-z8-re-venv/bin/python 'firmware decode/z-series/tools/reverse_z8_ui_version.py'
```

需要 Python `unicorn`、`capstone`，以及 `clang`、`ld.lld`、`llvm-objcopy`。脚本先验证输入哈希，执行原 getter 和原显示 helper。底层 `0x41022748` 被替换为合成版本 `03.11` 和指定返回码；字体、绘制函数被截获，记录送入文本系统的字符串。

| 场景 | 返回码 | 提交给文本系统的字符串 |
|---|---:|---|
| 原函数、backend 成功 | 0 | ` 3.11` |
| patch、backend 成功 | 0 | `3.11 P` |
| patch、backend 返回 2 | 2 | `3.11 P` |
| patch、backend 返回 4 | 4 | `3.11 P` |

每个场景同时断言 C 标签不变、`x19–x29`/SP 不变、10 字节缓冲区后的 guard 不变。结果见 `manifest.json`，原代码反汇编见 `code_landmarks.asm`。

探针的 `0x412A3800` 只是仿真 payload 地址，**未作为部署可用空间验证**。正式集成应由诊断固件 builder 选择和验证 payload 区域，并重新链接分支。这里也没有执行整页 builder、真实版本 backend 或真实文字渲染，所以字形宽度、页面布局及机身上菜单操作仍需实机确认。调试分支是否显示该标记不在本次保证范围内。

## 给独立诊断页面的线索

`0x403F2920` 接受 ASCII 指针、文本槽编号和字体标识；现有版本显示 helper 随后通过 `0x403F645C` 绑定文本对象，再调用 `0x403F621C` 激活对象。已有页面对象和文本槽的前提下，这条路径可作为只读诊断文本的参考。整页 builder 会查询附件版本和变更共享 UI 状态，不能直接当成通用文本页使用。

正常固件页 builder 的静态函数指针引用位于 EG 文件偏移 `0x4BF8970`（重定位 RAM 地址 `0xA028ED970`），可供菜单 callback 反查。另：`0x403AD6A4` 是菜单导航函数；`0x4054D3E0` 中的 `w0=2,w1=379` 指菜单组/菜单 ID，不是文本渲染调用。
