# Z8 C 3.11 P：设置菜单诊断页实验

已生成完整离线实验包：在设置列表末尾追加 **NFDG diagnostics**，进入后直接显示上一版诊断入口的固定信息；原来的固件版本页中，C 行显示 **3.11 P**，没有括号。原有 44 个设置条目和事件指针保留，列表增至 45 项。

实验包：[Z_8_0311_diagnostic_UI_3.11_P_EXPERIMENTAL.bin](Z_8_0311_diagnostic_UI_3.11_P_EXPERIMENTAL.bin)。只适用于原始 Z8 C 3.11 包，不能将地址套用于其他版本或机型。

**尚未连接或刷写相机，也未验证真实启动、LCD 绘制、滚动及恢复。封装校验和局部仿真通过不代表可安全刷写。**

## 预期操作与显示

1. 进入扳手图标的设置菜单，移动到列表末尾的 `NFDG diagnostics`。
2. 按 OK、右键或触摸该项，进入复用固件版本页布局的诊断页。
3. 页面显示四行固定信息；按 Done、返回、OK、右键或对应触摸动作回到设置列表。
4. 原来的“固件版本”入口继续存在，其中 C 行显示 `3.11 P`。

```text
NFDG diagnostics

ID    NFDG
P     1.0.0
M     Z8 2070
C     3.11 P

Done
```

这是预期内容示意，不是真机截图。P 行为既有诊断协议的版本，仍为 1.0.0；C 行为带补丁标记的基础固件版本。当前诊断内容只有固定身份与版本，不包含运行时传感器、错误日志、计数器或私有会话状态。诊断页不需要计算机发出 PTP 请求。

标题使用 ASCII 英文，36 种语言均返回同一标题并复用原“固件版本”文字的字体元数据；Done 使用固件原来的本地化文字。具体字形、布局和可见性仍需真机验证。

## 实现

源码：[构建工具](../../tools/build_z8_diagnostic_ui.py)、[AArch64 补丁](../../tools/patches/z8_0311_diagnostic_ui.S)、[离线验证器](../../tools/verify_z8_diagnostic_ui.py)。复用上一版 [PTP 诊断补丁](../z8_diagnostic/REPORT.md)、响应构造和封装工具。

| 部位 | 修改 |
|---|---|
| 设置菜单节点 group 2 / `0x297` | 将原 schema 中的行数从 44 改为 45，重定向到原 44 项加一项的新行表、事件指针表 |
| 新菜单行 | 文字编号 `0x7FF0`，局部对象编号 `0x4FFE`，沿用原固件版本条目的布局与标志 |
| 新诊断节点 group 2 / `0x600` | `0x403DB694` 的节点查找钩子仅接管这一组合；其他组合执行原 CMP 和后续代码 |
| 诊断页 | 克隆版本页 schema，只保留 Done 行；新绘制回调调用原文字显示辅助函数，并隐藏剩余版本字段和更新按钮 |
| 进入诊断页 | OK、右键、重复右键、触摸的目标为 `0x600`；移除原版本入口的更新准备回调 |
| 退出诊断页 | 返回、OK、右键、触摸调用原导航函数回到 `0x297`；不连接原固件更新事件 |
| 原版本页 C getter | `0x405AB454` 尾跳转接入新 trampoline，调用原版本查询后，在 10 字节缓冲区内写入 `3.11 P` |
| 文字资源 | `0x4032DB6C` 的上游编号归一化保留新编号；`0x4032E130` 返回 UTF-16 标题；八个元数据 getter 将新编号映射到原 `0x379` 的属性 |
| 诊断页标题 | 当前节点是新诊断页时，将模板的原 `0x379` 标题替换为新标题；其他页面保留原文字 |

新增节点必须可写：固件会向节点写入图形指针、选择位置和导航状态。因此节点放在初始化 RAM 副本尾部的 96 字节零填充中，文件偏移 `0x4DBF500`，运行地址 `0xA02AB4500`。没有将需要写入的节点放入只读载荷。

载荷共 **4,496 字节**，地址 `0x412A3200`；可执行部分结束于 `0x412A3618` 之前，与现有末尾函数的 `RET @ 0x412A31F0` 在同一 4 KiB 页。克隆的资源表延伸到下一页，仍处于启动描述表声明的映射范围中。构建器检查原映射、零填充、原指令、直接 PC 相对引用、完整 MOV 地址构造及绝对指针。RAM 节点还检查初始化映射、零填充和地址引用。

这些检查不能排除计算出的引用、启动清零、运行期间对填充区的复用或内存池不足，不能替代完整启动与真机测试。没有修改 Flash 写入、传感器或校准流程。

内部的 `Ver.03.11.b0` 字符串、升级版本解析和模块名称保持原样。只更改 UI 的 C 行和诊断页显示；USB 或升级逻辑使用的内部版本不会因显示标记而变成 `3.11 P`。版本 getter 保留原后端返回值；在后端状态为 0、2、4 的局部仿真中均写入补丁标记，原版本页如何处理错误状态仍由原回调决定。

## 复现

依赖 Python、Capstone、Unicorn 和 PATH 中的 `clang`、`ld.lld`、`llvm-objcopy`、`llvm-nm`。输出目录必须尚不存在；所有构建、校验和仿真通过后才发布产物。

```sh
cd "firmware decode/z-series"
/tmp/nikon-z8-re-venv/bin/python -B tools/build_z8_diagnostic_ui.py \
  --firmware Z_8_0311.bin --output /tmp/z8-diagnostic-ui-rebuild
/tmp/nikon-z8-re-venv/bin/python -B -m unittest discover -s tools -p 'test_*.py'
```

本工具没有相机连接或刷写选项。真机阶段尚需验证启动、设置列表滚动、各语言文字、按键/触摸返回、重复进入和已有功能；也尚未验证相机对同版本实验包的升级接受行为或独立恢复能力。
